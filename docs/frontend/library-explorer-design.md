# iOS 资料库探索页设计与实施规格

状态：评审后实施版  
目标平台：iOS 原生 SwiftUI（KMP 负责业务、数据与网络）  
支持语言：简体中文、繁体中文、English、日本語

## 1. 产品定位

资料库不是“我的片库”，也不是发现页的复制品。它是一个让用户在没有明确目标时也能自然闲逛、探索和建立观看兴趣的内容入口。

职责边界：

| 页面 | 核心职责 |
| --- | --- |
| 发现 | 当季内容、个性化推荐、编辑精选 |
| 资料库 | 分类、专题、榜单、搜索和开放式探索 |
| 动态 | 评价、评论、关注和社区内容 |
| 我的 | 收藏、评分、评价、片单、账号和设置 |

首屏原则：先给探索路径，再给内容；用户不输入关键词也能完成一次有效的浏览。

## 2. 评审结论与调整

产品/UI 评审确认：现有 `NativeLibraryView` 实际上是搜索页，缺少真正的资料库首页；搜索栏常驻、筛选入口出现过早、推荐标题复用了错误的登录文案，并且与发现页职责重叠。

因此实施版作以下调整：

1. 默认页只保留一个原生搜索按钮，搜索栏不常驻。
2. 大标题属于滚动内容，左对齐；右侧搜索按钮属于原生 Toolbar，位置和尺寸交给系统管理。
3. 默认内容按“浏览入口 → 主题漫游 → 榜单/新番/高分 → 推荐”组织。
4. “大家正在搜”和最近搜索只在搜索展开的空状态出现。
5. 所有内容通过现有服务端数据和筛选接口生成，不在客户端伪造作品列表。
6. 刷新只使用系统下拉刷新，不增加页面内刷新按钮。
7. 不叠加自定义顶部白色遮罩；顶部过渡由真实滚动容器和系统 `.scrollEdgeEffectStyle(.soft, for: .top)` 管理。

## 5. 交互规格

### 5.1 浏览入口

- 类型：打开类型筛选结果；首版使用 TV/Web/OVA/剧场版/其他等已有接口字段。
- 专题：打开专题列表；服务端尚未提供专题实体时，使用服务端首页分区作为可返回的主题卡，不在客户端硬编码作品集合。
- 榜单：打开评分排序结果，保留评分人数和排序说明。
- 新番：打开“本季”结果，组合年份与连载状态筛选。

### 5.2 搜索

- 入口是 Toolbar 原生搜索按钮，不使用常驻 `.searchable`。
- 输入使用本地状态；提交时使用现有 `/search/subjects`。
- 现有 `/search/discovery` 提供趋势词和推荐作品。
- 搜索成功后保存最近搜索；历史只保留用户本机最近若干条，并提供删除/清空。
- 搜索请求必须取消或丢弃过期响应；同一游标不能重复请求。
- 筛选 Sheet 支持类型、播出状态、年份区间和排序。

### 5.3 滚动与材质

- 页面只有一个真实纵向 `ScrollView`。
- 大标题放在滚动内容顶部，而非 Toolbar 标题。
- 右侧搜索按钮放在 `ToolbarItem(placement: .topBarTrailing)`，保持原生尺寸和点击反馈。
- 使用 `.scrollEdgeEffectStyle(.soft, for: .top)` 作为唯一顶部渐变模糊来源。
- 不放置固定高度背景、不放置手动渐变、不隐藏系统滚动边缘材质。
- 内容底部增加系统安全区间距，避免被 Tab Bar 遮挡。
- `.scrollIndicators(.hidden)`；滚动条不作为视觉元素展示。

### 5.4 状态

| 状态 | 行为 |
| --- | --- |
| 首次加载 | 显示分区骨架；单分区失败不影响其他分区 |
| 有缓存 | 先展示缓存，再静默刷新 |
| 下拉刷新 | 保留原内容，使用系统刷新控件，失败显示局部提示 |
| 搜索中 | 只替换结果区域，不闪烁整个页面 |
| 无结果 | 说明原因，给出清除筛选和浏览类型动作 |
| 分页失败 | 保留已有结果，只在列表尾部显示重试 |
| 离线 | 有缓存显示缓存；无缓存显示离线说明 |
| 减少动态效果 | 关闭轮播自动切换和复杂位移动画 |
| 减少透明度 | 玻璃降级为不透明系统表面 |

## 6. API 与数据映射

首版复用现有接口，避免为了视觉改版引入假的数据层：

| UI 模块 | 数据来源 | 当前能力 |
| --- | --- | --- |
| 主题漫游 | `/home` 的 `sections` | 已有分区和作品 |
| 大家正在搜 | `/search/discovery` | 已有真实趋势词 |
| 精选作品 | `/search/discovery` | 已有推荐作品 |
| 榜单 | `/search/subjects?sort=rating` | 已有排序参数 |
| 本季新番 | `/search/subjects?airing=airing&year_from=...` | 已有筛选参数 |
| 类型浏览 | `/search/subjects?types=...` | 已有类型参数 |
| 搜索结果 | `/search/subjects` | 已有游标转换和分页 |
| 作品详情 | `/subjects/{id}` | 现有详情导航 |

后续服务端可提供 `/library/explore`，将专题、榜单、新番和小众宝藏作为独立分区返回，并带 `id/kind/items/nextCursor`。客户端不得把作品列表写死。

## 7. SwiftUI/KMP 边界

```text
SwiftUI NativeLibraryView
├── 页面状态、导航、搜索焦点、Sheet
├── 资源文案 AnimeL10n
├── NativeLibrarySection / Card / FilterChip
└── NativeAppModel
    ├── IosNativeAppFacade
    ├── KMP SearchRepository / CatalogRepository
    ├── Token/Keychain/缓存
    └── 后端 API
```

SwiftUI 只负责展示状态和用户意图；筛选值使用稳定 ID（如 `tv`、`airing`、`rating`），不要将语言文本作为业务条件。

## 8. 国际化和无障碍

新增固定文案全部进入四套 `Localizable.strings` 与 `AnimeL10n.Key`。作品标题、专题标题、趋势词等服务端/用户内容不进入资源文件。

- 分区标题使用 `.isHeader`。
- 搜索按钮朗读“搜索作品”；筛选按钮朗读当前已选条件数量。
- 作品卡朗读标题、类型、年份、评分来源和评分人数。
- 英文、日文长标题不能破坏卡片宽度；动态字体放大时允许网格降为单列。
- 繁体资源使用“搜尋、篩選、專題、評分”等完整用词。
- 任何可见操作都不能依赖颜色、星星或图标单独表达。

## 9. 验收标准

功能：

- 默认资料库是探索首页，不是空搜索页。
- 默认只有原生搜索按钮；点击后出现搜索输入、趋势词、最近搜索和筛选入口。
- 类型、专题、榜单、新番入口有明确返回路径。
- 搜索支持趋势词、筛选、游标分页、重试和空状态。
- 所有作品卡点击进入现有作品详情。
- 下拉刷新不清空原内容。

视觉：

- 标题左对齐并随滚动自然消失，不变成居中小标题。
- 右侧原生搜索按钮不随标题消失，尺寸不自定义。
- 顶部只有系统滚动边缘渐变模糊；不出现白块、硬切断层或第二层手动遮罩。
- 底部内容不会被原生 Tab Bar 遮挡，滚动条不显示。
- 同一横向轨道海报高度一致，卡片标题和评分节奏统一。

工程：

- 不新增硬编码用户可见文案；CI localization guard 通过。
- 网络请求不阻塞主线程；过期搜索结果不会覆盖新结果。
- 支持四种语言和 Dynamic Type。
- SwiftUI iOS Simulator 构建/启动通过，设备 IPA 通过 GitHub Actions 构建。

## 10. 首版实施边界

本次 iOS 首版在不等待新增后端 `/library/explore` 的前提下，使用现有真实接口完成可用的探索闭环：

- `/home` 提供主题漫游分区；
- `/search/discovery` 提供趋势词和精选作品；
- `/search/subjects` 提供无关键词榜单、当季筛选、类型筛选、搜索、排序和游标分页；
- `/subjects/{id}` 继续提供统一作品详情。

后续服务端新增专题实体和题材标签能力后，只需替换探索数据适配层，不改变本页的导航、搜索、卡片和状态设计。
