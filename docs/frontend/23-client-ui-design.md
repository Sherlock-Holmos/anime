# 客户端界面设计：Apple 风格能力接入

## 设计原则

- 内容优先：页面先展示作品、动态和账户状态，操作放在上下文附近。
- 单一主动作：每个页面只突出一个主要动作，次要操作使用低强调按钮或菜单。
- 反馈可恢复：加载、空状态、离线和失败状态保持原内容，并说明下一步。
- Liquid Glass 克制使用：玻璃用于根导航、悬浮工具和短暂反馈；作品卡、评论卡保持高对比实面，避免文字漂浮在复杂背景上。

## 页面结构

### 发现 / 播出日历

发现页标题区右侧放置「播出日历」按钮。日历页顶部为返回、标题和横向日期选择器；日期选择器只显示短星期和日期，选中项使用系统 tint 色胶囊。下方按评分降序展示作品卡：海报、标题、年份/类型、Bangumi 评分和「查看作品」。

状态包括：首次加载骨架、无数据空状态、离线缓存提示、请求失败重试。日期切换不改变导航栈，只替换内容。

### 社区 / 动态与通知

社区页使用顶部 segmented control 切换「动态 / 通知」。动态保留现有全站/讨论筛选；通知按时间倒序排列，未读项用浅色 tint 背景和小圆点区分。点击通知先标记已读，再根据上下文跳转作品、评价或片单。

### 评论举报

评论卡保留「回复」和「删除」；对非本人评论提供「更多」菜单。举报使用底部 sheet，先选择垃圾信息、骚扰、剧透、违法或其他，再填写可选补充说明，提交后关闭 sheet 并显示一次性反馈。

### 片库与账户中心

片库卡片的次要操作为「移出收藏」，成功后卡片淡出并刷新数量。账户中心把「导出我的数据」放在隐私分组，把「注销账户」放在危险操作分组；注销按钮使用错误色、二次确认，并明确说明数据删除不可撤销。

## 无障碍与跨平台

- 所有图标按钮提供中文语义标签，触控目标不小于 44 dp/pt。
- 不依赖颜色单独表达未读、错误和危险状态，同时提供文字说明。
- iOS 不做低版本系统兼容，根导航使用官方 SwiftUI Liquid Glass；业务组件保持 Compose Multiplatform 共用，保证 Windows 调试和 GitHub Actions iOS 构建路径一致。
