# Anime Apple 设计基线

> 基线编号：`ADS-1.0`
> 生效日期：2026-08-12
> 适用范围：Anime Desktop、Android、Web 端的产品界面
> 平台目标：Desktop 对标 macOS 应用；紧凑窗口与移动端对标 iOS 应用
> 规范状态：Approved

## 1. 定位与边界

Anime 的视觉目标不是复制 macOS 或 iOS 的系统应用，也不是在所有平台模拟一套 Apple 控件。目标是吸收 Apple 软件的核心设计方法：内容优先、层级清楚、材质克制、排版精确、交互可预期，并保留 Anime 自己的媒体社区品牌。

本规范定义成品应呈现的品质和实现约束。Apple Human Interface Guidelines 是方法参考，不构成复制 Apple 商标、专有图标或受限资产的授权。

### 1.1 共同原则

1. **内容先于装饰**：海报、剧照、标题和用户内容承担主要视觉注意力。
2. **层级少而明确**：一个页面通常只有背景、内容表面、浮层三个深度级别。
3. **留白建立秩序**：优先用间距和排版分组，不依赖边框把每个元素圈起来。
4. **材质服务上下文**：玻璃仅用于导航、工具条、弹层和 Hero，不铺满普通卡片。
5. **动作可预测**：点击、返回、关闭、选中和加载的反馈必须符合平台习惯。
6. **密度适配设备**：Desktop 提供高效浏览和键鼠操作；移动端保证单手触达与连续阅读。
7. **真实内容决定色彩**：界面本身保持中性，作品图像提供情绪色。

### 1.2 明确禁止

- 大面积纯黑背景与纯白高对比边框同时出现。
- 每张卡片都使用高亮描边、阴影或实时模糊。
- Desktop 直接放大移动端布局，或移动端压缩 Desktop 双栏。
- 为了“高级感”叠加无意义渐变、光斑、发光描边和悬浮胶囊。
- 使用 Material 默认 TopAppBar、NavigationBar、Ripple 或 Elevation 作为最终视觉。
- 复制 SF Symbols、Apple Logo 或只允许在 Apple 平台使用的资源。

## 2. 平台表达模型

| 维度 | Desktop / macOS 取向 | Mobile / iOS 取向 |
|---|---|---|
| 根导航 | 左侧固定 Sidebar，支持键盘快捷键 | 底部全宽 Tab Bar，始终显示图标与文字 |
| 内容密度 | 中高密度，多列、主辅栏、悬停反馈 | 中低密度，单列、分组列表、触控优先 |
| 页面标题 | 内容区顶部，紧凑但有稳定留白 | 大标题可随滚动收拢，首屏强调上下文 |
| 主要动作 | 工具栏右侧或内容标题旁 | 底部安全区附近或内容块内全宽动作 |
| 返回 | 页面内容左上角、鼠标侧键和快捷键 | 系统返回、边缘手势和左上返回动作 |
| 弹层 | Popover、Dialog、独立窗口 | Sheet、全屏 Cover、Alert |
| 选择 | Sidebar、Segmented Control、菜单 | Tab、Segmented Control、Sheet 选择器 |
| 指针反馈 | Hover、Tooltip、光标和焦点环 | 无 Hover；按压、触感和状态切换 |

平台差异只改变表达方式，不改变路由、数据状态和功能可达性。

## 3. 信息架构与视觉层级

### 3.1 三层表面

| 层级 | 作用 | 默认表现 |
|---|---|---|
| Canvas | 窗口或页面背景 | 中性系统背景，不使用业务边框 |
| Content | 卡片、分组、输入区 | 不透明或 88%–96% 表面色，弱边界或无边界 |
| Floating | 导航、菜单、弹层、关键工具 | 半透明材质、柔和分隔、高于内容层 |

同一屏幕不得再创造第四套持续存在的视觉深度。临时模态通过 Scrim 与焦点管理表达，不通过更亮、更厚的描边表达。

### 3.2 信息权重

单个内容单元按以下顺序组织：

1. 主标题或主视觉；
2. 当前状态与首要动作；
3. 简介、评分、进度等决策信息；
4. 来源、时间、人数等元数据；
5. 诊断信息与次要操作。

同一行最多保留一个主动作。多个同级动作应进入工具组或更多菜单，破坏性动作不得与主动作同色。

## 4. Desktop Shell 基线

### 4.1 窗口

- 默认最小可用宽度为 `700dp`；低于该宽度切换紧凑 Shell。
- 窗口背景使用 `background`，内容不得覆盖系统标题栏的交互区域。
- 标题栏、Sidebar 和内容区必须属于同一色彩系统，禁止出现白色系统栏与深色应用内容割裂。
- Windows 构建应使用自有应用图标；窗口控制按钮保留系统行为和命中区域。

### 4.2 Sidebar

- 展开宽度：`220dp`。
- 内容左右内边距：`16dp`；顶部品牌区与导航区至少间隔 `24dp`。
- Sidebar 使用与内容背景相邻但可区分的材质；分隔仅使用单条低对比度细线或明度差，禁止高亮竖线。
- 导航项高度不低于 `44dp`，图标 `20–22dp`，选中态使用低饱和主色容器。
- 导航组标题为次级文本，不与页面标题争夺权重。
- 底部环境、同步或账号信息保持低权重，不能伪装成导航项。

### 4.3 内容区

- 内容最大宽度：`1320dp`；阅读正文最大宽度：`720dp`。
- 内容水平边距：标准窗口 `24dp`，宽窗口 `32dp`；不得紧贴 Sidebar。
- 页面标题与首个内容块的距离为 `24–32dp`。
- 宽屏优先使用主栏 + 辅栏，而不是把单栏无限拉宽。
- 列表、卡片和 Hero 必须对齐同一条内容起始线。

### 4.4 键鼠与焦点

- 可点击卡片在 Hover 时只改变表面明度、轻微描边或 `1dp` 高度感，不出现未裁切矩形遮罩。
- Hover、Pressed 和 Focus 必须被组件的圆角裁切。
- 键盘焦点环清晰但不过亮，焦点移动顺序与视觉顺序一致。
- 常用根导航支持 `Ctrl+1…4`；返回支持平台标准快捷键。

## 5. Mobile Shell 基线

### 5.1 页面骨架

- 默认单列，水平安全边距 `16dp`；中等宽度设备可增加到 `20–24dp`。
- 页面支持系统状态栏、导航栏和显示缺口安全区。
- 大标题用于根页面，详情页使用上下文标题和返回动作。
- 内容可以滚动到 Tab Bar 下方，但必须增加底部安全留白，最后一项不可被遮挡。

### 5.2 Tab Bar

- 可见内容高度 `62dp`，另加系统底部安全区。
- 使用全宽底部材质，不采用遮挡内容的超大悬浮胶囊。
- 每项由 `22dp` 图标和 `12sp` 标签组成；选中态使用 `primary`，未选中使用次级前景色。
- 根目的地保持四项：发现、资料库、动态、我的。
- 选择新 Tab 时保留各 Tab 的列表位置；重复点击当前 Tab 回到顶部。

### 5.3 触控

- 所有交互目标至少 `48×48dp`。
- 同一行的相邻图标按钮必须留出可识别间隔。
- 主动作优先靠近拇指区域；危险动作通过确认 Sheet 或 Alert 二次确认。
- 不依赖 Hover、右键或 Tooltip 才能发现功能。

## 6. 页面模板

### 6.1 浏览型根页面

结构为：页面标题 → 可选 Hero → 内容分组 → 横向内容轨道或自适应网格。每个分组只显示一个“查看全部”入口，并必须具备真实导航行为。

### 6.2 搜索页

搜索框是页面的首要输入，不单独套一层厚重外框。输入、清除和搜索动作形成一个统一控制组。Desktop 结果可双列；Mobile 结果为单列。

### 6.3 详情页

- 首屏包含返回、海报、标题、核心元数据和最多两个关键动作。
- Desktop 在宽屏使用海报 + 信息双栏；Mobile 使用海报与文字纵向组合。
- 评分来源必须区分 Anime 与 Bangumi。
- 简介正文使用阅读宽度；作品信息作为辅助栏或分组列表。
- 社区内容属于 Anime 后端；外部 Bangumi 内容必须明确标注只读来源。

### 6.4 个人中心

顺序为：账号身份 → 同步/绑定状态 → 个人统计 → 收藏与内容入口 → 外观和偏好。账号绑定属于账号中心，不应散落在普通设置项中。

### 6.5 状态页面

Loading、Empty、Offline 和 Error 使用同一内容骨架。错误文本面向用户，技术异常进入诊断信息；重试动作位于说明之后，禁止把堆栈信息作为页面主视觉。

## 7. 排版与图标

- 字体使用运行平台系统字体栈；中文优先匹配系统中文字体。
- 大标题 `34/41sp`，页面标题 `28/34sp`，区块标题 `20/28sp`，正文 `16/24sp`。
- 中文标题默认不增加字间距；数字统计启用等宽数字。
- 一个页面最多使用三种明显字重。
- 图标采用项目自有圆润线性体系，统一视觉盒、端点和线宽。
- 图标按钮必须有语义标签；纯装饰图不进入无障碍树。

## 8. 材质、动效与反馈

- 普通卡片默认无阴影；通过背景明度和间距分组。
- 玻璃只用于 Shell、Hero、Popover、Sheet 和 Dialog。
- 按压反馈不得改变控件布局尺寸；禁止点击后按钮被拉长或文字位移。
- 标准局部过渡 `120–220ms`，页面强调过渡不超过 `360ms`。
- 自动轮播在用户交互后暂停；减少动态效果时禁用自动切换和位移过渡。
- 操作成功优先使用局部状态变化或短暂 Toast/Snackbar，不弹出无必要对话框。

## 9. 无障碍与产品质量

- 正文对比度不低于 `4.5:1`；大字与关键图形不低于 `3:1`。
- 支持 200% 字体，布局允许换行而不是裁切。
- 状态不能只由颜色表达。
- Desktop 支持完整键盘操作；Mobile 支持 TalkBack 阅读顺序和系统返回。
- 减少透明度时玻璃降级为不透明 `surface`；减少动态效果时保留不超过 `100ms` 的必要淡变。

## 10. 实现映射

| 规范 | 当前事实源 |
|---|---|
| 主题颜色 | `core/designsystem/.../AnimeTheme.kt` |
| 间距、圆角、尺寸、动效 | `core/designsystem/.../AnimeTokens.kt` |
| 卡片与按钮 | `core/designsystem/.../AnimeComponents.kt` |
| 玻璃角色 | `core/designsystem/.../AnimeGlass.kt` |
| Desktop Sidebar / Mobile Tab Bar | `shared/app/.../AnimeApp.kt` |

Feature 不得复制这些数值。设计调整必须先修改本规范和 Token，再迁移组件。

## 11. 验收清单

- [ ] Desktop 在 700、1024、1440、1920 宽度下无异常拉伸。
- [ ] Mobile 在 360、390、412、600 宽度下无横向溢出。
- [ ] Sidebar 与内容区之间没有高亮粗竖线。
- [ ] Mobile Tab Bar 不遮挡最后一项内容。
- [ ] Hover、Pressed、Focus 均被圆角正确裁切。
- [ ] 页面没有无意义的嵌套卡片和重复描边。
- [ ] Light、Dark 模式保持相同的信息层级。
- [ ] 所有独立动作在点击前后尺寸稳定。
- [ ] 200% 字体、减少动态和减少透明度可用。
- [ ] 空、错、离线、加载状态与内容状态使用同一布局语言。
